# jvk Cleanup & Optimization Plan

Produced 2026-07-27 from a full-repo audit (memory layer, renderer core, graphics layer,
offscreen/ECS) cross-checked against current Vulkan community best practice (Khronos Vulkan
Guide, VMA docs, NVIDIA Do's & Don'ts, vkguide, zeux.io, MoltenVK user guide). Sources cited
inline where the recommendation comes from outside the repo.

The recent bug history (L2 leak `8fc37ef`, MoltenVK descriptor-pool crash `965a16c`, upload
queue race `dad7434`) is not three isolated bugs — each is an instance of a systemic pattern
this plan targets: **implicit cross-file lifecycle contracts** (belt rotation living in
Renderer, not L2), **message-thread/worker shared state without locks**, and **unchecked
Vulkan results**. Several unfixed siblings of each are listed below.

> **Architecture direction (Gavin, 2026-07-27):** community consensus wins over any in-repo
> design docs. `ARCHITECTURE.md` and the bespoke L1/L2/M/V memory design are treated as
> HISTORICAL — the destination is the community-standard stack (VMA for all allocation,
> timeline-semaphore-keyed deletion, vkguide-style per-frame lifetime, Khronos-sample
> descriptor and swapchain patterns). Where a Phase 1/2 fix below would only patch a bespoke
> system that Phase 5 replaces outright, prefer the replacement — the sequencing section at
> the bottom marks which fixes get subsumed.

## Phase 1 — Correctness: use-after-free, races, layout violations

These are siblings of the three recently fixed bugs. Ordered by severity.

### P1.1 `Memory::V::grow` destroys an in-flight vertex buffer (UAF)
`Memory.h:685-693` retires the old buffer; `flushRetired()` (`:695-702`) destroys ALL retired
buffers in `beginFrame` (`:610-615`) — called for slot S^1 whose fence only proves frame N-1
finished, while frame N (which recorded binds against the old buffer, `Renderer.cpp:1031-1034`)
may still be executing. The dead `VertexRingBuffer.h:121-140` has the correct per-slot
DeletionQueue discipline — port it. Fix: route V's retirements into the per-slot FrameSlot
rotation (Phase 3.1), flushed only when that slot's fence next signals.
Also: `grow` resets `writeHead = 0` mid-frame (`Memory.h:692`) — document why it's safe
(State::draw re-binds on handle change) or carry the head over.

### P1.2 `recordingRetains_` race — direct sibling of `dad7434`
`Renderer::retain()` bare `push_back` (`Renderer.h:224`) vs worker `std::move` + `clear`
(`Renderer.cpp:818-819, 889-890`) and `flushRetains` (`:122-123`). Message-thread producers
outside the isBusy() gate: `Shader::update` (`Shader.h:148`), `Cache::getTexture` via
`Shader::set` (`Cache.h:383,431`). A lost push = pin never recorded = `Cache::evict` frees a
`VkImage` in a submitted command buffer; a torn vector = double-unpin/underflow.
Fix: guard with `uploadLock_` (three lines away) and **swap into a member buffer** rather than
move (keeps capacity; see Phase 4.13).

### P1.3 `retire()` / `activeRetireSlot_` race
`Renderer.h:397-398` reads non-atomic `activeRetireSlot_` (worker writes it,
`Renderer.cpp:388`) and pushes into the bucket the worker clears one line later. Only caller:
`Shader::update` (`Shader.h:105`) — same user-callable path as P1.2. Slot semantics also
wrong (a record-time retire lands in the PREVIOUS frame's bucket). Fixed structurally by
Phase 3.1 (single locked FrameSlot).

### P1.4 `Memory::M::getLayout` torn read
`Memory.h:421` reads `layouts[id]` unlocked while `registerLayout` (`:413`) can reallocate the
vector from another thread (editor A's worker builds a Shader while editor B's worker builds a
lazy Pipeline). The `:417-420` immutability comment covers entries, not the vector buffer.
Fix: `std::deque`, or take the lock (it's a pointer read), plus layout dedup (Phase 3.2).

### P1.5 Unbounded growth on the swapchain-skip path — sibling of `8fc37ef`
`Renderer::execute` early-return (`Renderer.cpp:362`) skips `staging_.recycle/moveActiveTo`
(`:390,417`), `flushUploads` (`:412`), and the retains rotation (`:889`). A persistent
OUT_OF_DATE storm (minimized window on Windows — steady state, not exotic) with one 1080p
`Shader::update` feed grows `L2::activeBlocks` ~8 MB per tick (~500 MB/s), grows
`pendingUploads_`/`recordingRetains_` monotonically, and pin counts climb so LRU eviction
can never fire. Fix: on the skip path still rotate staging into the slot arrays, coalesce
`pendingUploads_` by dstImage, and/or stop recording while acquire is failing.

### P1.6 L2 blocks parked against the wrong slot
`moveActiveTo` runs mid-execute on the worker (`Renderer.cpp:417`); message-thread
`staging().alloc()` calls landing after the park (`Cache.h:405`, `Shader.h:135`) are filed
against frame N but their upload records in frame N+1 → recycled after frame N's fence, while
frame N+1's copy may still read them. Narrow window, silent texture corruption.
Fix: park at a well-defined boundary (e.g. under `uploadLock_` in the same swap as the pending
queues), or tag blocks with the frame that actually records them.

### P1.7 Glyph pages sampled in `UNDEFINED` layout; unsound cache key
- Glyphs rasterize during replay (`ColorDraw.h:409` → `GlyphAtlas::createPage`,
  `GlyphAtlas.h:240-277`) AFTER `prepare`/`stageDirtyPages` ran (`Renderer.cpp:402`), so a new
  page is bound and sampled with zero uploads and no layout transition — the exact
  "expects SHADER_READ_ONLY_OPTIMAL, current layout UNDEFINED" failure mode of `dad7434`,
  reached by another route. New glyphs on existing pages render one frame stale.
  Fix: rasterize at record time (`Graphics::drawGlyphs` has font + glyph ids) so prepare
  covers staging, or add a post-replay staging + barrier pass.
- `GlyphKey` (`GlyphAtlas.h:37-46`) holds a raw `Typeface*` (no ref) → address reuse serves
  wrong glyphs forever (entries never evict); key omits `metricsKind` which rasterization
  uses (`GlyphAtlas.h:140`). Fix: `Typeface::Ptr` + metricsKind in key + hash.
- `findSpace` (`GlyphAtlas.h:222-238`) mutates cursor state on pages it rejects; no bounds
  guard at the write site (`:188`).

### P1.8 `~Shader` leaves queued uploads pointing at a freed `VkImage`
`Shader::update` queues `uploadDynamic` against `ownedImage`; `~Shader` (`Shader.h:448-479`)
drains pins but never cancels pending uploads → next `flushUploads` records a copy into a
destroyed image. The resize path already knows the fix (`cancelUploads`, `Shader.h:104`);
call it for every ownedImage in the dtor (needs a Renderer back-pointer or global cancel).

### P1.9 `Shader::load()` not idempotent
`reflectShader` (`Shader.h:507-555`) appends to `bindings_` without clearing; second `load()`
= duplicate bindings → invalid descriptor layout; `created_` short-circuit keeps the stale
pipeline. Fix: clear state at top; assert/tear down on re-load.

### P1.10 `State` clip stack persists across frames → permanent black window
`State::begin`/`invalidate` (`Renderer.cpp:898-917`) never resets `clipRectStack_`,
`currentClipBounds_`, `stencilDepth_` (`Renderer.h:178-180`). One unbalanced push (exception
unwind, `setPaintingIsUnclipped` component) permanently shrinks the scissor or poisons the
stencil ref for every future frame. Fix: 3 lines in `State::begin`.

### P1.11 `ShaderPipeline` scissor clamp bug
`ShaderPipeline.h:81-86` clamps offset but not extent — a clip starting at x=-40 leaks 40 px
past its right edge. `State::draw` (`Renderer.cpp:1002-1021`), `PathPipeline.h:210-225`,
`ClipPipeline.h:154-169` all have the correct math. Fix via the shared `setScissorClamped`
helper (Phase 3.11). Also: `ShaderPipeline::dispatch` is the only dispatcher of three that
omits the trailing `state.invalidate()` bookkeeping.

### P1.12 `colorB` render-pass initialLayout violation
`createSceneBuffers` (`RenderTarget.cpp:416-473`) never transitions colorB out of UNDEFINED,
but `effectRP_`/`sceneRPLoad_` declare `initialLayout = SHADER_READ_ONLY` (`:341,315`). First
effect pass after startup and after every resize violates
VUID-vkCmdBeginRenderPass-initialLayout-00900. Fix: one-shot transition at the end of
createSceneBuffers.

### P1.13 `vkDeviceWaitIdle` without `queueLock()` — external-sync violations
The lock contract (`Renderer.h:539-553`) is honored by submits but not by:
`RenderTarget.cpp:630` (resize), `:71` (~SwapchainTarget), `:747,:792` (OffscreenTarget),
`Renderer.cpp:155` (forceDrainAll), `Device.cpp:80` (~Device), `AudioProcessorEditor.h:86,199`,
`ShaderImage.cpp:389`. Editor A's teardown racing editor B's worker submit is the same class
as the queue-lock bug. Also `RenderTarget.cpp:617-623` calls resize→deviceWaitIdle while
HOLDING queueLock from endFrame — cross-editor stall. Longer term Phase 5.2 (timeline
semaphores) removes most device-idles entirely.

### P1.14 `NSViewGenerator`: uninitialized pointer, double retain, hardcoded scale
`NSViewGenerator.h:40` `void* ptr;` never initialized (dtor→release reads garbage if create()
never ran); `NSViewGenerator.mm:57` alloc + `:66` retain vs one release at `:77` — the
`JVKMetalView`/`CAMetalLayer` leak on every teardown; `:64` `contentsScale = 2.0` hardcoded
(wrong on non-Retina; `AudioProcessorEditor.h:130` already calls this out).

### P1.15 Teardown ordering hazards
- `teardownVulkan` (`AudioProcessorEditor.h:190-233`) destroys the 11 pipelines then leaves
  `Renderer`'s raw pipeline pointers dangling until `renderer_` dies at `:216` — null them or
  destroy renderer first.
- The render timer is stopped only in the base dtor, AFTER derived members die; a message-loop
  pump during derived destruction can fire `render()` on a half-destroyed component. Stop the
  timer earlier or document the subclass contract.
- `~GradientAtlas` (`Cache.h:45-49`) destroys a live-bound image/set with no pin — safe only
  by member-order accident; make it FrameRetained or destroy explicitly post-idle.

## Phase 2 — Error-handling discipline (VkResult)

Not one `VkResult` is checked in ShaderImage (784 lines); most creates in RenderTarget.cpp /
Pipeline.cpp / Memory.h are unchecked. The worst chains:

- **`vkQueueSubmit` unchecked (`RenderTarget.cpp:596,786`)** → fence never signals → worker
  blocks forever in `vkWaitForFences(UINT64_MAX)` (`:532`) → `waitForIdle()` spins the message
  thread → `stopThread(2000)` force-kills the worker mid-Vulkan-call on close.
  Fix: check submit; finite fence timeout with device-lost escape.
- **`vkAcquireNextImageKHR`: `imageIndex` uninitialized; only OUT_OF_DATE handled**
  (`RenderTarget.cpp:534-536`) — SURFACE_LOST/DEVICE_LOST fall through to
  `swapImages_[garbage]`. SURFACE_LOST is routine for embedded plugin windows.
- **No `VK_ERROR_DEVICE_LOST` handling anywhere** (grep: zero hits). TDR → permanent failing
  loop, no fallback, `isVulkanAvailable()` never goes false.
- **`built_/created_/ready` set unconditionally on failure**: `Pipeline.cpp:67`,
  `Shader.h:430`, `ShaderImage.cpp:115` → `vkCmdBindPipeline(VK_NULL_HANDLE)` later.
- **`M::growPool` pushes a pool entry even when `vkCreateDescriptorPool` failed**
  (`Memory.h:547-548`) — then every alloc selects the poisoned `used==0` entry forever. This
  is the same MoltenVK fault class `965a16c` fixed. `M::alloc` null returns unchecked at 5 of
  6 call sites (`Cache.h:37,395,483`, `RenderTarget.cpp:468`, `Shader.h:196`).
- **`L2::createBlock` / `V::createSlot` unchecked** (`Memory.h:306-318, 660-672`) →
  null `mapped` → blind memcpy at `Cache.h:84,406,495`, `GlyphAtlas.h:100`, `Memory.h:624`.
- **`findMemoryType` returns 0 on failure** (`Memory.h:8-16`) → wrong memory type silently, or
  `memset(nullptr)` segfault in ShaderImage (`ShaderImage.cpp:233`).
- `RenderTarget.cpp:103` `caps` uninitialized when `vkGetPhysicalDeviceSurfaceCapabilitiesKHR`
  fails (contrast `:92` which zero-inits); swapchain create unchecked then used (`:176-183`).
- `ShaderImage.cpp:525` uninitialized `VkShaderModule` used/destroyed on failure (UB).

Mechanics: introduce a `JVK_CHECK(expr)` macro (log + propagate/mark-failed), a per-Renderer
`deviceLost_` latch that fails `execute()` gracefully and flips `isVulkanAvailable()`, and
audit every `vkCreate*/vkAllocate*` site. VMA adoption (Phase 5.1) deletes many of these
sites outright.

## Phase 3 — Consolidation (one system per job)

### 3.1 One `FrameSlot` rotation
`retired_` (`Renderer.h:496`), `stagingBySlot_` (`:504`), `retainsBySlot_` (`:517`) are three
parallel per-slot arrays flushed/filled at six different points. Replace with:
```cpp
struct FrameSlot {
    std::vector<jvk::Image>          retiredImages;
    std::vector<VkBuffer/VkDeviceMemory pairs> retiredBuffers;  // for Memory::V
    std::vector<Memory::L2::Block>   staging;
    std::vector<FrameRetained*>      pins;
};
std::array<FrameSlot, kSlots> slots_;  // one lock, one retire(), one flush()
```
Fixes P1.1/P1.2/P1.3 structurally, makes the `8fc37ef` leak class impossible (one flush
handles everything incl. ~Renderer), removes non-atomic `activeRetireSlot_`, and absorbs
`DeletionQueue` (43 lines wrapping two clears, plus its namespace-lookup trap:
`DeletionQueue.h:28-29` names `jvk::core::Buffer/Image` which don't exist — it compiles only
because lookup escapes to `jvk::`; including the dead `core/Image.h` anywhere would silently
re-point the types).

### 3.2 One descriptor system
Four live systems: `Memory::M`, PathPipeline's private pool (`PathPipeline.h:89-111`),
ClipPipeline's duplicate SSBO layout (`ClipPipeline.h:72-82` — byte-identical to
PathPipeline's), ShaderImage's per-set pools (`ShaderImage.cpp:311-325`). Consolidate on `M`:
- **Dedupe layouts by content hash + refcount** in `registerLayout` — fixes the per-Shader
  `VkDescriptorSetLayout` + dedicated 256-set `VkDescriptorPool` leak (`Shader.h:194`,
  `Memory.h:393-415, 435-455`; 50 open/close cycles × 5 shaders = 250 leaked layouts+pools).
- ClipPipeline takes `pathPipeline_->ssboSetLayout()` like PathBlurPipeline already does
  (`PathBlurPipeline.h:53`).
- Give `GlyphAtlas` a destructor (`clear()` is currently dead code — every editor close leaks
  one set per page and permanently inflates pool `used`).
- Community note: keep cached sets (right model for this workload — Khronos descriptor-
  management sample measured 44→27 ms from caching); consider `VK_KHR_push_descriptor`
  (MoltenVK-supported) for the one-texture-per-draw user-shader path later.

### 3.3 One CPU-backed atlas
`GradientAtlas` (`Cache.h:24-111`) and `GlyphAtlas` (`GlyphAtlas.h`) are the same object
(CPU mirror → dirty region → L2 stage → upload → image + set) with different rasterizers.
Extract `CpuBackedAtlas`: GlyphAtlas gains dirty-RECT uploads (today one new 32×32 glyph
re-stages the full 16 MB page, `GlyphAtlas.h:98-102`, forcing an oversized L2 block), 
GradientAtlas gains page overflow (today it silently reuses the last row on overflow,
`Cache.h:68`), both get one correct descriptor lifetime.

### 3.4 One fullscreen-pass pipeline class
Effect/HSV/ShapeBlur/PathBlur pipelines (1,003 lines across 4 files) differ only in
PushConstants struct, setLayoutCount, compareOp, and frag SPIR-V; init/destroy/applyPass are
byte-identical (table in audit). `template<class PC> class FullscreenPass` → ~330 lines
(saves ~670). Also resolves the silent bind-order divergence between the pairs.
The pass descriptor also carries the per-pass `readMarginX/Y` from 4.16, so declaring an
effect and declaring its ROI requirements are the same act — a new effect cannot forget
its apron.

### 3.5 One pipeline builder
`Pipeline.cpp:70-250` already has the config-driven builder; ClipPipeline (`:215-343`),
PathPipeline (`:356-470`) and Shader (`Shader.h:286-431`) hand-roll it, incl. the 13-line
UIVertex input description ×3. Extend `PipelineConfig` with `{setLayouts, pushRanges,
vertexInput: none|UIVertex, stencilPassOp}` and route all through `buildVariant` (~300 lines
saved; VkResult checks land in one place).

### 3.6 Merge the blur shaders
`path_blur.frag` = `shape_blur.frag` with one distance function swapped (140 shared lines;
its comments literally say "See shape_blur.frag"). One shader with `shapeType == 4 → pathSDF`
deletes `path_blur.frag`, `PathBlurPipeline.h` (246 L), and the 19.5 KB blob
(UI2DShaders.h:3342-4565). `blur.frag` is a third cut-down copy — share `blur_kernel.glsl`
via the already-enabled include directive. (~1,600 lines total.)

### 3.7 Regenerate embedded shaders properly
- Emit `uint32_t` words instead of `unsigned char` in compile.sh: UI2DShaders.h 5,065 → ~1,300
  lines AND fixes the alignment/strict-aliasing violation at `AudioProcessorEditor.h:443-446`
  and `Shader.h:288-290` (`reinterpret_cast<const uint32_t*>` on char arrays).
- Fold `NoiseShader.h` and `ShaderRegionVert.h` into the generator: both are hand-maintained
  (.spv dated Jul 3 vs Jul 24 for the rest); `CMakeLists.txt:133` lists `shader_region.vert`
  as a dependency but compile.sh never compiles it — editing the GLSL silently does nothing.
  `noise.frag` is absent from both lists. (~290 lines + removes the stale-blob trap.)

### 3.8 Rebuild ShaderImage on OffscreenTarget + Shader (784 → ~150 lines)
ShaderImage hand-rolls a third copy of: resource creation (`Resource.h` exists), the offscreen
render pass/framebuffer/sync (`OffscreenTarget` exists), and SPIR-V reflection
(`Shader.h:507-555` exists — and handles the spirv-reflect zero-size-SSBO quirk that
ShaderImage's copy doesn't, which is why its manual `storageBufferSize` param and the
zero-size-SSBO bug exist). While rebuilding, fix:
- Unwaited `vkResetFences`/`vkResetCommandBuffer` on `fence[curr]` (`ShaderImage.cpp:712-713`)
  — relies on unspecified same-queue completion order.
- Missing subpass dependency + no barrier between color write and `vkCmdCopyImageToBuffer`
  (`:195-201`, `:763`); missing HOST_READ barrier before CPU read (none in the whole repo).
- Readback thread-safety: `getImage()` returns a reference into an image `render()` rewrites
  and `setSize()` replaces — torn pixels / dangling ref. Fix: double-buffered `juce::Image`
  published through an atomic index; return by value (refcount pin). Advertise the real
  threading contract or add the guard `render()` lacks.
- `loadTexture`'s `vkDeviceWaitIdle` + `submitImmediate`(→`vkQueueWaitIdle`) — process-wide
  stalls per call; per-call transient buffer/memory; full `convertedToFormat` copy.
- `setSize` full teardown/rebuild per resize event with no debounce (hundreds during a live
  drag) + lossy FPS restore (`1000/getTimerInterval()` → 60 becomes 62).
- Also note: ShaderImage.cpp is compiled into every consumer but its only user is one
  `EXCLUDE_FROM_ALL` example. Consider making it opt-in until the rebuild.
Best practice for the "read on any thread" goal (Phase 5.2): readback memory must be
HOST_CACHED (VMA `HOST_ACCESS_RANDOM`), waits via timeline semaphore `vkWaitSemaphores` +
poll API — never `vkQueueWaitIdle`/`vkDeviceWaitIdle` on the shared device.

### 3.9 Delete `Device::staging_`
Exists solely for the 4-byte black-pixel upload (`Cache.h:494`) and its blocks never rotate —
a 4 MB L2 block pinned for the Device lifetime. Give `submitImmediate` a scoped staging
buffer; delete the member and the "category (c)" caveat (`Device.h:28-32`).

### 3.10 Merge SwapchainTarget/OffscreenTarget frame plumbing
beginFrame/endFrame bodies are ~80% identical (`RenderTarget.cpp:528-625` vs `:760-787`).
A protected `beginRecording(slot)`/`submitRecording()` lets the Phase 2 VkResult fixes land
once. (Moot for OffscreenTarget if Phase 0 deletes it; keep if 3.8 adopts it.)

### 3.11 Shared replay helpers
- `setScissorClamped()` — 4 copies, one buggy (P1.11).
- `emitCoverQuad()` — 5 hand-written quad tables (ClipPipeline.h:189-207, Graphics.h:333-351,
  ColorDraw.h:106-123,135-143,155-163).
- Merge `PushClipPath`/`PopClipPath` replay branches (`Renderer.cpp:564-615`, 25-line clones;
  make `ClipShapeParams` the push-constant layout — it's re-declared field-for-field at
  `ClipPipeline.h:43-53`).
- Merge the BlurShape/BlurPath mode/pass loops (`Renderer.cpp:719-739` vs `:770-788`).
- `emitPaddedSdfQuad` + op-context factory in ColorDraw (4× repeated padding math, 6× repeated
  preamble — `ColorDraw.h:201-331`).
- `pushFilled<Op,Params>` record helper in Graphics (7× repeated prolog).
(~200 lines total, plus the bug fixed by construction.)

## Phase 4 — Performance

### CPU / allocation churn (message thread, per frame)
1. **Hoist `jvk::Graphics` to an editor member.** It's stack-constructed per frame
   (`AudioProcessorEditor.h:374`), so `scratchPoints_/scratchSegStack_/scratchSegments_/
   stateStack_` start at capacity 0 every frame — the "allocation-free after first frame"
   comment (`Graphics.h:1023-1026`) is false across frames. Add `beginFrame()`.
2. **Stop deep-copying `juce::FillType` per draw** (`Renderer.h:402` captureFill; a gradient
   fill heap-allocates a ColourGradient per primitive; `saveState` pays it again per
   component). Intern by hash (hashGradient exists, `Cache.h:442`) → POD `{colour, gradRow}`.
3. **Persist `GradientAtlas::hashToRow_` across frames** (`Cache.h:51-55` clears it every
   frame → every gradient re-rasterizes 256 `getColourAtPosition` calls + re-hash ×2 + map
   node churn). Generation-stamp instead; upload only dirty rows (`:82-84` currently copies
   the whole `[0,cursor)` prefix). Also removes the record-side pre-registration double-hash.
4. **`getTexture` row memcpy** — `Cache.h:408-417` does `getPixelColour` per pixel (1M virtual
   dispatches for 1024²). `Shader::update` (`Shader.h:110-143`) already shows the
   B8G8R8A8+memcpy fast path.
5. **Batch glyphs into one draw** — `ColorDraw.h:406-445` issues one `vkCmdDraw` + scissor
   check per glyph and calls `font.getTypefacePtr()` (atomic refcount) per glyph. One draw of
   6×N verts per run; hoist the typeface.
6. **Implement `FillRectList`** (`Graphics.h:268-271` explodes N rects into N pushes + N
   FillType copies + N draws).
7. **Cache the inverse transform for `getClipBounds()`** (`Graphics.h:209-221` inverts a
   matrix per call; JUCE calls it per child).
8. **`Shader::set/update` by `StringRef`/handle** — per-call `juce::String` heap alloc + linear
   String compares (`Shader.h:22,83,156,165`); host code calls these per frame.
9. **Slim `FillPathParams`** — 400 B (6 UIVertex) memcpy'd per fillPath (`Params.h:157-163`);
   derivable at replay from ~40 B.
10. **Narrow `state.invalidate()`** after path/clip ops (`PathPipeline.h:256`,
    `ClipPipeline.h:212` nuke ALL bound state → full rebind after every path op).
11. **Build pipelines at init/async, not mid-replay** (`Renderer.cpp:795-796` compiles inside
    the open render pass on first use; `Shader::ensureCreated` same, `ShaderPipeline.h:60`).
    NVIDIA: never create pipelines mid-frame. Pair with Phase 5.4 pipeline cache.
12. **`flushUploads` member double-buffers** (`Renderer.cpp:276-282` allocates two fresh
    vectors per frame and destroys the capacity), same for the retains swap (P1.2).
13. **`Cache::evict` cadence** — full map walk + atomic per entry per frame per editor
    (`Cache.h:190-214`); every N frames is fine.
14. **MSDF rasterization is synchronous on the worker inside the render pass**
    (`MSDF.h:201-272`, expensive error-correction mode, one glyph per pass) — moves to record
    time with P1.7; consider a budget/queue and a disk cache later.
15. `Shader`'s uniform buffer is single-buffered and written during record while the previous
    frame may read it (`Shader.h:568-575`, `ShaderPipeline.h:120-122`) — two `drawShader`
    calls in one frame see last-writer-wins. Per-slot ring like everything else.

### GPU
16. **Scissor effect passes to their region — via declared per-pass read margins (ROI
    back-propagation).** `BlurParams::region/scale` and `HSVParams::region/scale` are
    recorded then ignored (`Renderer.cpp:530,664-667`); BlurShape/BlurPath force full-extent
    passes + full-screen pre-copies (`Renderer.cpp:701,733,767,782`). Every blurred knob
    costs 2+ full-screen passes.
    **Mechanism (industry standard — Skia `filterBounds` reverse mapping / Core Image ROI
    callback / OpenFX RegionsOfInterest):** each effect pass declares the input rect it reads
    to produce a given output rect. For jvk's pass set a declared apron suffices:
    `struct EffectPassDesc { ...; int readMarginX = 0, readMarginY = 0; }` where
    `requiredInput(out) = out.expanded(readMarginX, readMarginY)` — separable blur declares
    `(radius, 0)` for the horizontal pass and `(0, radius)` for the vertical, Poisson
    shape/path blur declares `(radius, radius)`, HSV/tint/noise declare `(0, 0)`.
    The renderer then walks the pass chain BACKWARD from the final region (user region ∩
    clip bounds): pass N's output rect = pass N+1's requiredInput, clamped to the target
    extent (clamp is safe — the shaders already edge-handle, `9f21c0f`). Worked example
    (32×32 box, r=8, vertical then horizontal): horizontal outputs 32×32 and reads ±8 in x
    ⇒ vertical outputs 48×32 and reads ±8 in y ⇒ 48×48 of source. The same walk sizes the
    `preCopyIfClipped` copy region. Keep margins expressed in each pass's own output space
    so a future downsampled blur chain (dual-filter/Kawase for large radii) can insert a
    scale factor into the mapping without API change. Lands naturally with 3.4: the
    FullscreenPass base carries the pass descriptor array; the ROI walk is ~10 lines in
    replay.
17. Clip paths pay the O(pixels×segments) SDF walk twice (push AND pop full-cover quads,
    `Renderer.cpp:564-615`); the rrect fast path (Phase 0 note) skips the SSBO walk for the
    common rounded-rect clip.
18. Fixed footprint: ~60 MB/editor (2×8 MB V eagerly allocated — slot 1 never touched for
    offscreen; 16 MB CPU mirror + 16 MB GPU per glyph page; 4+4 MB gradient atlas; L2 blocks).
    V could allocate lazily; glyph CPU mirrors could shrink post-upload with dirty-rect
    uploads (3.3).

## Phase 5 — Vulkan modernization (community-verified)

1. **Replace the memory system with VMA** (per the architecture direction — this is the
   destination, not an internals swap). L1 dissolves into plain VMA allocations
   (`VMA_MEMORY_USAGE_AUTO` + usage flags); L2 and V become thin, purpose-named rings
   (`StagingRing`, `VertexRing`) over VMA custom pools with the linear algorithm; `Resource.h`
   keeps its RAII role holding a `VmaAllocation` instead of an L1 handle.
   Hand-rolled gaps this closes: process-wide 4096 `vkAllocateMemory` limit (real risk with
   multiple plugin instances sharing the Device — ShaderImage and V allocate dedicated),
   dedicated-allocation preferences for render targets, memory-type fallbacks,
   `VK_EXT_memory_budget`, leak/corruption detection.
   Crucially `HOST_ACCESS_ALLOW_TRANSFER_INSTEAD_BIT` collapses staging to **zero-copy on
   Apple Silicon unified memory** (the current L2→L1 copy is pure waste there) while keeping
   the staging path on discrete Windows GPUs. L2 currently also has zero offset alignment
   (`Memory.h:234-266` raw bump; works only because every caller size is a multiple of 4 —
   one odd size misaligns every later `vkCmdCopyBufferToImage` in the block); VMA or an
   `alignUp(head, optimalBufferCopyOffsetAlignment)` fixes it. L1's per-alloc granularity
   padding, never-returned 64 MB blocks, missing double-free/range validation, and the entire
   free-list/coalescing code (~150 lines that must be maintained and re-verified) all go away.
2. **Timeline semaphores** — SCOPE DECISION (perf gate, 2026-07-27): NOT converted as a
   standalone step. The fence/FrameSlot sync now works and is leak/race-free; converting it
   buys ~zero throughput (the device-idles it would remove are already off the hot path) at
   real regression risk. Timelines land WITH Phase 6, where GPU→CPU readback genuinely needs
   the any-thread wait primitive (`vkWaitSemaphores` + poll). Binary semaphores stay at the
   WSI boundary regardless. (Note: the instance is created for Vulkan 1.0 — Phase 6 must
   bump instance/device to 1.2 or enable VK_KHR_timeline_semaphore explicitly.)
3. **Swapchain sync polish**: per-image `renderFinished_` is already correct (matches the
   2021+ Khronos guidance; validation now enforces it). Remaining: `endFrame` indexes sync by
   member `currentFrame_` not `frame.frameSlot` (`RenderTarget.cpp:582,596` — breaks silently
   if frames-in-flight changes); resize destroys before create so `oldSwapchain` is always
   null (`:634,:174` — dead retirement path, full teardown per resize); consider per-image
   fences if non-FIFO present modes stay exposed. Keep FIFO default on MoltenVK.
4. **`VkPipelineCache` serialized to disk** (zeux header format: vendor/device/driver/UUID +
   hash, write-temp + atomic rename). On MoltenVK this also caches the SPIR-V→MSL conversion
   — significant editor-open speedup. One process-wide cache file.
5. **`VK_KHR_dynamic_rendering`** (core 1.3; MoltenVK supports): deletes the render-pass +
   framebuffer machinery (incl. the recreate-on-resize bookkeeping and the P1.12 class of
   initialLayout bugs — barriers become explicit). Medium effort; do after Phases 1-3.
6. **Command pools**: switch from `RESET_COMMAND_BUFFER_BIT` + per-buffer reset
   (`RenderTarget.cpp:14,561`) to pool-level reset (one pool per frame-in-flight per worker) —
   measured cheaper (Khronos sample), and drop `FREE_DESCRIPTOR_SET_BIT` wherever pools only
   ever reset.
7. **`VK_KHR_synchronization2`** where available for the barrier sites (nicer masks; jvk's
   masks are already mostly tight — keep the discipline).
8. MoltenVK config: defaults are right; always feature-query (it's a non-conformant layered
   implementation despite 1.3/1.4-level features).

## Phase 6 — Vulkan-backed juce::Image (jvk::ImageType / jvk::PixelData)

Goal (Gavin, 2026-07-27): jvk needs a real juce::Image backend — the SoftwareImageType
workarounds in host projects exist because jvk lacks one. The sanctioned JUCE extension
point is a custom `juce::ImageType` + `juce::ImagePixelData` pair (the `OpenGLImageType` /
JUCE-8 Direct2D precedent). Design (validated against this repo's audits):

- **`jvk::ImageType::create`** → `jvk::PixelData` holding `Device::Ptr` (image keeps device
  alive), a `jvk::Image` (VkImage+view+sampler via `Resource.h`, VMA-backed after 5.1), its
  descriptor, and dirty/backing state. On device-unavailable, fall back to constructing a
  SoftwarePixelData inside `create` so callers never see a null image.
- **`createLowLevelContext()`** → a `jvk::Graphics` over an offscreen render pass on the
  image. PREREQ: the OffscreenTarget rebuild (3.8/3.10) — it is currently dead code with
  four sync bugs and `Renderer::execute` would crash on its unpopulated scene buffers.
  CRITICAL: no Renderer-worker-per-image (Renderer spawns a thread per instance,
  `Renderer.h:556-575`) — image contexts use an immediate mode: record on the calling
  thread, submit under `queueLock()`, fence/timeline-wait when the context is destroyed.
  Effects ops inside an image context are optional v2 (need per-image ping-pong); the
  compliance surface (fills/paths/clips/text/images) is v1.
- **`initialiseBitmapData()`** — read mode: submit + wait + copy through HOST_CACHED staging
  with the TRANSFER→HOST barrier (note: NO HOST_READ barrier or invalidate exists anywhere
  in the repo today — this is new plumbing, per the Phase 5.7 readback recipe, NOT a copy of
  `ShaderImage::loadTexture`'s device-wide-idle model). Write mode: hand out staging, upload
  in a `BitmapDataReleaser` (the OpenGLFrameBufferImage pattern). Slow-but-correct escape
  hatch; document as such.
- **`clone()`** → `vkCmdCopyImage`. Subsections need nothing (JUCE's SubsectionPixelData
  forwards). `SingleChannel` → R8 + color-multiply sampling (this is what unlocks
  `clipToImageAlpha`). JUCE 8's ImagePixelData blur virtuals → map to the existing blur
  passes (check the tree's juce_Image.h for the exact set).
- **Wiring that pays**: (a) `getPreferredImageTypeForTemporaryImages` (`Graphics.h:472`)
  returns `jvk::ImageType` when the device is live → `setBufferedToImage` components render
  and composite zero-copy; (b) `drawImage` fast path — `dynamic_cast<jvk::PixelData*>`
  before the hash/cache lookup captures the descriptor directly and skips
  `hashImage`/`getTexture` entirely (the existing cache stays as the software/native-image
  fallback); (c) ShaderImage can hand out a jvk-backed image and drop its per-frame CPU
  readback when the consumer is a jvk context.
- **Lifetime discipline** (the SoftwareImageType lesson, now on jvk's side): a static
  jvk-backed image recreates the DllMain/device-teardown hazard with VkDevice in the D3D
  role. Debug-assert in `~PixelData` against static-teardown/message-thread-gone; document
  "never park jvk images in `juce::ImageCache`" (process-global static holder with a
  keep-alive timer). Multi-instance: images share the process Device — all submits under
  `queueLock`, allocation via VMA (5.1) keeps the 4096 budget safe.
- **Limit (accepted)**: plain `juce::Image(format, w, h)` hardcodes NativeImageType — no
  hook exists. Opt-in type + the preferred-temporaries hook is exactly the compliance level
  OpenGLImageType had.

## PERF GATE (added after checkpoint 3 — governs everything below)

Performance IS the product (Gavin: 4K/120 with as many effects/gradients/objects
as possible; orders of magnitude wanted). Rules:
1. Every checkpoint runs the benchmark PER MODE; a round that regresses any
   mode vs the prior checkpoint doesn't ship until fixed. First impressions
   count — investigate them, never dismiss them.
2. Structural/aesthetic refactors are subordinate to throughput. A dedup that
   costs a hot-path nanosecond needs a reason; one that costs a pass or a
   copy is rejected.
3. Known costs of correctness fixes (locks on shared containers, VkResult
   checks) must stay off per-draw hot paths — per-frame or per-object only.
Lesson already banked: the effect copy-back doubled full-window saturate
(caught by Gavin's first impression); per-glyph Typeface::Ptr key churn taxed
big text scenes. Both fixed by keeping the cheap path for the dominant case.

## Addendum: complex-path fill rewrite (round 6, 2026-07-27)

The Paths-benchmark audit (2.4 fps vs JUCE 24.8) traced the loss to the fill
algorithm itself: one bounds-covering quad per path whose EVERY fragment walked
the segment list (Y-strip binning reduced the walk but not the ~90% empty-fragment
overdraw, and its fwidth()-based AA streaked at strip boundaries — the reported
artifacts). Fills now use an exact tile+backdrop decomposition (piet-gpu class):

- `Graphics::fillPath` tiles the clip∩bounds region (16px, power-of-2 coarsening
  above a 65k-tile budget). Per tile: a local segment list (pad-2 bbox binning)
  and a backdrop winding at the tile's top-right corner (row-top crossings
  bucketed by column, suffix-summed). Tiles the path never touches are not
  drawn; interior runs merge into single flat quads; only edge tiles walk their
  few local segments.
- `path_sdf.frag` reconstructs the exact winding as backdrop + top-edge +
  descent crossings (derivation in the shader header) and uses derivative-free
  1px AA (`clamp(0.5 - signedDist, ...)`) — no fwidth, so the strip-boundary
  streaks are gone by construction.
- Exactness fuzz-verified: 1.2M fragments across 3000 random multi-contour
  scenes vs brute-force ray casting, zero mismatches. The fuzz also exposed a
  real bug: the flattener didn't implicitly close open subpaths (juce fills do);
  it now closes every chain, which also corrects clip/blur winding.
- Cross-CPU/GPU float consistency at tile edges: crossing x is computed with
  statement-split mul/add on the CPU and `precise` in GLSL (bit-identical), and
  tile boundaries are exact integer floats.
- clip.frag / path_blur.frag intentionally keep Y-strip binning (winding-only /
  per-tap distance — no fwidth, no overdraw problem of the same kind).

Follow-ups if the benchmark still falls short: cross-frame caching of the tiling
keyed on (path, transform), scale-aware flatten tolerance.
